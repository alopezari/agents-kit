- Triage reads WordPress names (current_user_can, $wpdb, dbDelta, hooks, block markup) as risk signals only in WordPress repos, detected from the repo's top level or turned on and off with a `packs` file in the repo's overlay. A non-WordPress change no longer picks up lenses or a high tier from them, and triage prints which packs it applied. Only the top level is read: a monorepo or a site under `www/` needs `wordpress` in that file. When detection can't conclude (a git failure, an unreadable or invalid marker file), triage stops and names the cause instead of sizing the change without the pack.
