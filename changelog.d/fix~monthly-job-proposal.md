- The monthly review-mining job saves its proposal when `~/.agents` is a link to the kit's checkout: Claude Code matches its permission rules against resolved paths, so every write of the model was refused there. The model now writes only inside its run directory, under its resolved path, and the job publishes the proposal it leaves there, with the rule checks, as `research/proposals/<month>.md`, renamed over the earlier one so a failed copy can't cut it. A run fails when the model exits non-zero or leaves no proposal, without moving `last-success`, and its last line on stderr names the model's exit status and its log, never the model's reply.
- The weekly health report names the tests that failed instead of `FAILURES ABOVE`, gives the suite's exit status and last line when no test is named, and keeps a failing block's traceback and detail (up to 40 lines a block, or the output's last 20 lines when no test failed by name). It no longer writes errors to its log when no repo overlay has a PHPUnit baseline or `logs/` holds no `.jsonl` file.
- `tests/run.sh` names a section that exits non-zero without printing a `FAIL ` line: `FAIL <section> exited <status> without naming a failing test`.
