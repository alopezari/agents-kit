- The shell guard now follows a variable through more of a command before judging a recursive delete. An assignment still counts after a heredoc whose body the shell only passes along, after quoted text that merely mentions `read` or `unset`, and after an `&&` behind another plain assignment or behind a `cd` into an existing absolute folder, while nothing before it could have removed that folder (comments, assignments, and `mkdir`, `cat`, `echo`, `printf`, `touch`, `ls` or `true` that run no other command); in a single-quoted string the command runs (`bash -c '…'`), only when that string is the first thing it runs. Inside a `for` loop over literal words, a delete such as `rm -rf /tmp/x/$p` is judged once per word, up to 64 combinations. A double-quoted string the command runs (`bash -c "…"`) gets none of this: the calling shell expands its variables first, so the guard reads it as before. Whenever the command could be read two ways, the guard blocks it as before: a heredoc the shell may run, `eval`, `source`, an alias, `IFS`, `declare`, `local`, `readonly`, a `read`, `export` or `unset` whose variable name is only known at run time, an `&&` behind an assignment to a name that starts with a digit, `case`, a function, or a loop that changes directory outside a subshell of its own, holds a heredoc or has its variable set elsewhere; a delete after a `cd` in a loop's subshell is judged without the loop's words. Deletes of the main checkout, home, `/` or unknown paths are still blocked.
- Three kinds of command the guard used to let through are now blocked. An assignment in a list sent to the background (`S=/tmp/x && job & rm -rf $S/y`) never reaches the shell that runs the delete, one with a redirection attached (`S=/tmp/x>file`) may not happen, and a variable named onto a `printf` or `read` option (`printf -vS …`, `read -aS`) is set again before the delete. A redirection written with a space inside it after an assignment chain (`S=/tmp/x && make 2>& 1; rm -rf $S/y`) is blocked too; write it `2>&1`.
- The guard's denials now say how to get through: a delete of an unresolved variable says to write the path out or, when the path isn't computed at run time, to assign the variable in a statement of its own, `git branch -D` points to `git branch -d` and `git worktree add --detach`, and every denial tells a subagent to report the blocked command to the agent that started it instead of asking a user it can't reach.
- A `find` that only lists PRODUCT.md, DESIGN.md or `.impeccable/` with grouped tests (`\( … -o … \)`) no longer asks for approval; one that deletes them still does.
