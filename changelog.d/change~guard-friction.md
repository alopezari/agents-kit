- The shell guard now follows a variable through more of a command before judging a recursive delete. An assignment still counts after a heredoc whose body the shell only passes along, after quoted text that merely mentions `read` or `unset`, and after an `&&` behind a `cd` into an existing absolute folder or another plain assignment. Inside a `for` loop over literal words, a delete such as `rm -rf /tmp/x/$p` is judged once per word, up to 64 combinations. Whenever the command could be read two ways (a heredoc the shell may run, `eval`, `source`, an alias, `IFS`, `declare`, `case`, a loop variable set elsewhere), the guard blocks it as before. Deletes of the main checkout, home, `/` or unknown paths are still blocked.
- The guard's denials now say how to get through: a delete of an unresolved variable says to write the path out or assign the variable in a statement of its own, `git branch -D` points to `git branch -d` and `git worktree add --detach`, and every denial tells a subagent to report the blocked command to the agent that started it instead of asking a user it can't reach.
- A `find` that only lists PRODUCT.md, DESIGN.md or `.impeccable/` with grouped tests (`\( … -o … \)`) no longer asks for approval; one that deletes them still does.
