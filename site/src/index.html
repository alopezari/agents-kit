// how it fits together

Edit once, every harness follows

The installer links one set of instructions and skills into each harness and registers the same hooks in each one's settings. Pi has no hook config, so a small adapter translates its events into the same calls.

Every hook speaks one contract, JSON in and a decision out, so adding another harness means writing one adapter, not rewriting the checks.

// guardrails

A seatbelt, not a cage

Agents work freely until a command can't be taken back. Then the guard stops it and says why, and the agent asks you. It catches mistakes; it doesn't claim to stop a determined attacker.

When a check can't be satisfied honestly, the agent is asked to continue once, then reports it to you under Blocked on me. It never loops, and it never loosens a test to get past one.

// evidence

Written from what reviewers actually flag

The instructions come from an analysis of about {{review_comments}} human review comments. The defects they catch most are checked before any human sees the change.

One path fixed, others forgotten

A new guard must hold on every path to the same outcome: other callers, CLI and cron, preview and real run.

Text that lies

Comments, help text and PR descriptions must be true of the code as it stands now.

Tests that can't fail

A bug fix comes with a test that fails without it, for the reason the report describes.

"Failed" treated as "empty"

A query error is not "nothing found". No empty catches, no silent fallbacks.

// profiles

Modular by design: one core, many profiles

The core holds nothing tied to one employer, client or project. Everything specific lives in profiles: separate, usually private repositories you layer on top with one command.

Keep one for your day job, one per client, one for open source or side projects. Each adds its own repository notes and checks, skills, rules for shared systems and the repositories the monthly job learns from, and the core stays generic and shareable.

~
$ ~/.agents/install.sh --profile ~/profiles/work
$ ~/.agents/install.sh --profile ~/profiles/client-a
adds: repos/ overlays · skills/ · mcp-writes.json · review-mining/
repos/<repo>/

Notes agents read in that repository, and a verify script when the automatic checks aren't enough.

skills/<name>/

Skills for one kind of work, available to every harness alongside the core ones.

mcp-writes.json

Which tools write to your team's shared systems, so they need your approval first.

// learning loop

It gets better, and asks you first

A weekly health check reads the hook log. Each month a job classifies new review comments, measures what slipped past review, and compares cost per merged pull request with the months before the kit. A mid-month scan looks for new harness and model features worth adopting.

None of them applies a change. They write proposals, with diffs, and you decide what goes in.

// install

Five minutes, safe to re-run

The installer wires every harness it finds, keeps the hooks you already have, and backs up anything it replaces. The doctor reports what's missing and changes nothing; the test suite passes once it's clean.
